Техническое описание (ТО) внешней компоненты NativeApiSearch для 1С:Предприятие
1. Общее назначение
Внешняя компонента (AddIn) NativeApiSearch реализует полнотекстовый поиск по коллекции документов внутри 1С:Предприятие. Компонента построена на базе Rust-библиотеки Tantivy — полнотекстового поискового движка, аналогичного Apache Lucene. Компонента подключается к 1С через native_api_1c и предоставляет набор методов и свойств, доступных из встроенного языка 1С.

Область применения:

Быстрый полнотекстовый поиск по большим коллекциям строк (справочники, документы, регистры).

Хранение индекса в оперативной памяти (RAM) без записи на диск.

Динамическое добавление и удаление документов без полной перестройки индекса.

Ключевые особенности:

Индекс создаётся в оперативной памяти (Index::create_in_ram), не требует файловой системы.

Схема документа фиксирована: два поля — id (GUID, хранимое) и text (строка, индексируемая).

Компонента потокобезопасна: доступ к движку защищён Arc<Mutex<SearchEngine>>.

Все ошибки внутри методов «проглатываются» и возвращаются в виде кодов/пустых значений, чтобы не выбрасывать панику в 1С.

2. Архитектура
Компонента состоит из двух логических слоёв:

text
┌─────────────────────────────────────────────────┐
│              NativeApiSearch (AddIn)            │
│  ┌───────────────────────────────────────────┐  │
│  │ Публичные методы и свойства для 1С        │  │
│  │  - CollectionJson (свойство)              │  │
│  │  - HelloWorld()                           │  │
│  │  - BuildIndex()                           │  │
│  │  - Search(Запрос, Лимит)                  │  │
│  │  - Add(Ид, Текст)                         │  │
│  │  - Remove(Ид)                             │  │
│  │  - Count()                                │  │
│  └───────────────────────────────────────────┘  │
│                      │                          │
│                      ▼                          │
│  ┌───────────────────────────────────────────┐  │
│  │  Arc<Mutex<SearchEngine>>                 │  │
│  │  ┌─────────────────────────────────────┐  │  │
│  │  │ SearchEngine                        │  │  │
│  │  │  - index: Option<Index>             │  │  │
│  │  │  - id_field: Option<Field>          │  │  │
│  │  │  - text_field: Option<Field>        │  │  │
│  │  │  - total: usize                     │  │  │
│  │  └─────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
                      │
                      ▼
              ┌───────────────┐
              │   Tantivy     │
              │  (in-RAM)     │
              └───────────────┘
Слой 1 — SearchEngine — «чистая» логика работы с Tantivy: построение индекса, поиск, добавление, удаление. Не зависит от 1С.

Слой 2 — NativeApiSearch — обёртка-AddIn: макрос #[derive(AddIn)] генерирует FFI-экспорты (GetClassObject, DestroyObject, Init, Done, DllMain), а также связывает публичные поля-функции с методами 1С.

3. Схема индекса
Индекс Tantivy имеет фиксированную схему из двух полей:

Поле	Тип в Tantivy	Флаги	Назначение
id	text	STORED	GUID документа. Хранится, но не индексируется (поиск по нему невозможен, но используется для удаления).
text	text	TEXT	Основной текст. Индексируется с токенизацией, доступен полнотекстовый поиск.
Пояснения:

STORED — значение сохраняется в индексе и возвращается при поиске.

TEXT — поле токенизируется (разбивается на слова), индексируется, но не хранится в исходном виде; для его возврата при поиске используется STORED-версия. В данной схеме TEXT включает STORED по умолчанию в новых версиях Tantivy, но для гарантии корректного возврата текста в Search можно при необходимости заменить на TEXT | STORED.

4. Публичный интерфейс для 1С
4.1. Свойство CollectionJson / КоллекцияJSON
Параметр	Значение
Тип	Str (строка)
Чтение	Да
Запись	Да
Имя (EN)	CollectionJson
Имя (RU)	КоллекцияJSON
Назначение: входной JSON-массив документов для первичного построения индекса методом BuildIndex.

Формат:

json
[
  { "id": "0f8fad5b-d9cb-469f-a165-70867728950e", "text": "Первый документ" },

Правила:

Оба поля (id, text) необязательны: при отсутствии подставляется пустая строка.

Дополнительные поля игнорируются.

Если JSON невалиден, BuildIndex вернёт -1.

4.3. Метод BuildIndex / ПостроитьИндекс
Параметр	Значение
Аргументы	нет
Возврат	Int
Имя (EN)	BuildIndex
Имя (RU)	ПостроитьИндекс
Назначение: полностью пересоздать индекс в оперативной памяти на основе JSON, записанного в свойство CollectionJson.

Код	Описание

4.4. Метод Search / Поиск
Параметр	Значение
Аргумент 1	Str — поисковый запрос
Аргумент 2	Int — лимит результатов
Возврат	Str — JSON-массив найденных документов
Имя (EN)	Search
Имя (RU)	Поиск
Назначение: выполнить полнотекстовый поиск по полю text.

Правила:

Синтаксис запроса — стандартный для Tantivy QueryParser: слово, "фраза", слово1 AND слово2, слово1 OR слово2, слово* (префикс), -слово (исключение).

Если limit > 10, значение принудительно снижается до 10.

Если limit <= 0, возвращается пустой массив [].

Если запрос пуст или состоит из пробелов, возвращается [].

Если индекс не построен, возвращается [].

Любая внутренняя ошибка приводит к возврату [].

Формат ответа:

json
[
  { "id": "11111111-1111-1111-1111-111111111111", "text": "Молоко", "score": 0.2876821 },
  { "id": "22222222-2222-2222-2222-222222222222", "text": "Хлеб",   "score": 0.2231435 }
]
Поле	Описание
id	GUID документа.
text	Текст документа.
score	Релевантность (чем больше — тем лучше).
Пример на 1С:

bsl
Результат = Компонента.Поиск("Молоко", 10);
Массив = Новый ЧтениеJSON;
Массив.УстановитьСтроку(Результат);
Данные = ПрочитатьJSON(Массив);
Для Каждого Стр Из Данные Цикл
    Сообщить(Стр.id + " → " + Стр.text + " (score=" + Стр.score + ")");
КонецЦикла;
4.5. Метод Add / Добавить
Параметр	Значение
Аргумент 1	Str — идентификатор (GUID)
Аргумент 2	Str — текст документа
Возврат	Int
Имя (EN)	Add
Имя (RU)	Добавить
Назначение: добавить один документ в существующий индекс.

Возвращаемые значения:

Код	Описание
1	Документ успешно добавлен.
0	Индекс не построен, либо ошибка Tantivy (writer, добавление, commit).
Побочные эффекты:

При успехе total увеличивается на 1.

Индекс не перестраивается — документ дописывается инкрементально.

Дубликаты по id не проверяются (если нужно — используйте Remove перед Add).

Пример на 1С:

bsl
Компонента.Добавить("33333333-3333-3333-3333-333333333333", "Сыр");
4.6. Метод Remove / Удалить
Параметр	Значение
Аргумент 1	Str — идентификатор (GUID)
Возврат	Int
Имя (EN)	Remove
Имя (RU)	Удалить
Назначение: удалить документ по id из индекса.

Возвращаемые значения:

Код	Описание
1	Операция удаления выполнена (commit прошёл).
0	Индекс не построен, либо ошибка Tantivy.
Особенности:

Удаление выполняется через delete_term по полю id — Tantivy помечает документ как удалённый; физически он исчезнет при следующем merge.

Если документа с таким id не было — Tantivy всё равно вернёт успех (это не ошибка).

total уменьшается на 1 (не ниже нуля) независимо от того, был ли документ.

Двойное удаление одного и того же id приведёт к неверному счётчику total.

Пример на 1С:

bsl
Компонента.Удалить("33333333-3333-3333-3333-333333333333");
4.7. Метод Count / Количество
Параметр	Значение
Аргументы	нет
Возврат	Int
Имя (EN)	Count
Имя (RU)	Количество
Назначение: вернуть текущее количество документов в индексе по внутреннему счётчику total.

Возвращаемые значения:

Код	Описание
>= 0	Текущее значение total.
0	Если мьютекс не захвачен (крайне маловероятно).
Важно: значение total — это внутренний счётчик компоненты, а не реальное число документов в Tantivy. Он увеличивается при BuildIndex и Add, уменьшается при Remove. При удалении несуществующего id счётчик всё равно уменьшается — это может привести к расхождению с фактическим числом документов в индексе.

Пример на 1С:

bsl
Сообщить("Документов в индексе: " + Компонента.Количество());
5. Сценарии использования
5.1. Первичная загрузка и поиск
bsl

// 1. Формируем JSON
Массив = Новый Массив;
Для Каждого СтрокаСпр Из Справочники.Товары Цикл
    Массив.Добавить(Новый Структура("id, text",
        Строка(СтрокаСпр.Ссылка.УникальныйИдентификатор()),
        СтрокаСпр.Наименование));
КонецЦикла;

ЗаписьJSON = Новый ЗаписьJSON;
ЗаписьJSON.УстановитьСтроку();
ЗаписатьJSON(ЗаписьJSON, Массив);
Компонента.КоллекцияJSON = ЗаписьJSON.Закрыть();

// 2. Строим индекс
Кол = Компонента.ПостроитьИндекс();

// 3. Ищем

bsl
// Добавление

                    НовыйТовар.Наименование);

6. Обработка ошибок
Компонента придерживается «тихой» стратегии обработки ошибок: паники и исключения Rust не пробрасываются в 1С. Вместо этого методы возвращают специальные значения:

Метод	Признак ошибки
BuildIndex	Отрицательное число (-1, -2, -3).
Search	Пустая строка [].
Add	0.
Remove	0.
Count	0.
Рекомендация: в коде 1С проверять возвращаемые значения и вести журнал регистрации для диагностики.

7. Потокобезопасность
Движок обёрнут в Arc<Mutex<SearchEngine>>, что позволяет безопасно разделять его между вызовами.

Методы BuildIndex, Search, Add, Remove, Count захватывают мьютекс на время работы.

Метод HelloWorld не обращается к движку и не блокируется.

При конкурентных вызовах из разных потоков 1С (что маловероятно, но возможно) вызовы сериализуются мьютексом.

Ограничение: Tantivy IndexWriter не является Sync для одновременной записи; в данной реализации writer создаётся заново при каждом Add/Remove, что снимает проблему, но создаёт накладные расходы.

8. Ограничения и известные особенности
Индекс только в RAM. При перезапуске сеанса/компоненты индекс теряется — нужно пересоздавать через BuildIndex.

Лимит поиска — 10. Жёстко задан в search_inner; больше 10 результатов за один вызов получить нельзя.

Счётчик total не является истиной. Он не синхронизирован с реальным состоянием индекса Tantivy (удаления, повторные добавления).

id не индексируется. Поиск по id через Search невозможен — только через Remove.

Нет проверки дубликатов id. Add позволяет добавить несколько документов с одинаковым id.

Нет сохранения индекса на диск. Каждый запуск — построение с нуля.

text в схеме — только TEXT, без STORED. В зависимости от версии Tantivy это может привести к тому, что поле text не вернётся в результатах поиска. Если это критично — заменить на TEXT | STORED.

Отсутствует Drop/Done с очисткой. Индекс освобождается вместе с компонентой.

11. Рекомендации по доработке
Добавить STORED к полю text (TEXT | STORED) для гарантированного возврата текста в результатах поиска.

Вынести лимит поиска в свойство (например, MaxSearchResults) вместо жёсткого 10.

Синхронизировать total с реальным состоянием — использовать searcher.num_docs() вместо ручного счётчика.

Проверять существование id перед Add/Remove для избежания дубликатов и некорректного счётчика.

Добавить метод Rebuild без сброса, либо метод Update(id, text) для замены документа.

Добавить сохранение индекса на диск (Index::create_in_dir) для persistence между сеансами.

Логировать ошибки через OutputDebugString или возвращать коды с детализацией (например, отдельный метод LastError).

Добавить валидацию GUID в 1С-обёртке перед вызовом Add/Remove.

Раздел 13. Сборка компоненты
Сборка компоненты NativeApiSearch выполняется по методике, описанной в статье на Инфостарт «Внешние компоненты Native API на языке Rust — Просто!» . Весь процесс сводится к нескольким шагам: подготовка окружения, настройка Cargo.toml, установка зависимостей и компиляция в динамическую библиотеку (DLL).

13.1. Подготовка окружения
Для сборки необходимы следующие инструменты :

Инструмент	Назначение	Ссылка
Rust (rustup)	Компилятор и менеджер пакетов Cargo	https://www.rust-lang.org/tools/install

13.1.1. Установка Rust
Скачайте и запустите установщик rustup-init.exe со страницы https://www.rust-lang.org/tools/install .

При установке на Windows возможны два варианта:

Вариант А — с MSVC (рекомендуется для Windows):

Нажмите 1 (default installation).

Установщик сам скачает и настроит toolchain stable-x86_64-pc-windows-msvc.

Для этого должна быть установлена Visual Studio Community с компонентом «Desktop development with C++» .

Вариант Б — с GCC (MinGW):

Введите 2 (customize installation).

В качестве host triple укажите x86_64-pc-windows-gnu .

Убедитесь, что GCC (MinGW-w64) установлен и доступен в PATH.

rustup toolchain install stable-i686-pc-windows-msvc

# Для GCC (альтернатива)
rustup toolchain install stable-x86_64-pc-windows-gnu

13.1.3. Проверка установки
bash
rustc --version
cargo --version
rustup toolchain list
Все три команды должны вывести версии без ошибок .

13.2. Настройка Cargo.toml
В корне проекта создайте/отредактируйте файл Cargo.toml. Ключевой момент — указание crate-type = ["cdylib"], чтобы результатом компиляции стала динамическая библиотека, пригодная для подключения в 1С .

toml
[package]
name = "native_api_search"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
native_api_1c = "0.10.5"
native_api_1c_core = "0.10.5"
native_api_1c_macro = "0.10.5"
tantivy = "0.22"
serde_json = "1"
Пояснения:

native_api_1c — основная библиотека для Native API компонент .

tantivy — полнотекстовый поисковый движок.

serde_json — для разбора CollectionJson и сериализации результатов поиска.

13.3. Установка зависимостей
Из корня проекта выполните :

bash
cargo add native_api_1c utf16_lit
cargo add tantivy serde_json
Либо просто вручную добавьте зависимости в Cargo.toml (см. раздел 13.2) и выполните cargo build — Cargo сам скачает все крейты.

13.4. Структура проекта
Рекомендуемая структура :

text
native_api_search/
├── Cargo.toml
├── src/
│   └── lib.rs          ← весь код компоненты
└── target/             ← создаётся автоматически
    └── x86_64-pc-windows-gnu/
        └── debug/
            └── native_api_search.dll
Важно: имя проекта в Cargo.toml (name = "native_api_search") определит имя итогового файла DLL.

13.5. Команды сборки
13.5.1. Debug-сборка (для разработки)
bash
cargo build --target=x86_64-pc-windows-gnu
Готовая компонента появится здесь :

text
target\x86_64-pc-windows-gnu\debug\native_api_search.dll
13.5.2. Release-сборка (для продакшена)
bash
cargo build --release --target=x86_64-pc-windows-gnu
Результат:

text
target\x86_64-pc-windows-gnu\release\native_api_search.dll
Release-сборка оптимизирована по скорости и размеру, рекомендуется именно её использовать в 1С.

13.5.3. Сборка под MSVC (если выбран этот toolchain)
bash
cargo build --release --target=x86_64-pc-windows-msvc
13.5.4. Сборка под 32-битный клиент 1С (учебная версия)
Если вы используете 32-битную учебную версию 1С, соберите под i686 :

bash
cargo build --release --target=i686-pc-windows-gnu
13.6. Альтернативный способ: сборка через Docker
Если вы не хотите устанавливать Rust локально, можно собрать компоненту в Linux-контейнере с кросс-компиляцией под Windows . Пример скрипта:

bash
docker run --rm -v "$PWD":/work -w /work \
    rust:latest \
    bash -c "rustup target add x86_64-pc-windows-gnu && \
             apt-get update && apt-get install -y gcc-mingw-w64-x86-64 && \
             cargo build --release --target=x86_64-pc-windows-gnu"
Этот способ удобен для CI/CD и не требует установки Rust/MSVC на рабочую машину .

13.7. Использование сгенерированного кода через конструктор
Если вы используете Конструктор внешних компонент 1C (native API) , процесс отличается:

В конструкторе на закладке «Функции» опишите методы (HelloWorld, BuildIndex, Search, Add, Remove, Count) с русскими и английскими именами.

На закладке «Сборка» нажмите кнопку «Собрать» — конструктор сгенерирует:

Проект на C++ (с CMakeLists.txt);

Проект на Rust (со скелетом крейта).

Сначала соберите Rust :

bash
cd rust
cargo build
Появится статическая библиотека (.lib/.a).

Затем соберите C++ в Visual Studio:

Откройте CMakeLists.txt через «Open Folder» в VS;

Соберите проект — получите финальную DLL;

Статическая библиотека Rust линкуется автоматически через CMake .

Этот способ удобен, когда нужно автоматически генерировать обвязку для десятков методов, но для нашего случая (6 методов) проще собирать напрямую через cargo build, как в разделе 13.5.

13.8. Упаковка в ZIP с манифестом (для кроссплатформенной загрузки)
Если компонента должна автоматически подгружаться через ПодключитьВнешнююКомпоненту("ОбщийМакет.МояКомпонента"), упакуйте DLL в ZIP вместе с manifest.xml :

xml
<?xml version="1.0" encoding="UTF-8"?>
<bundle xmlns="http://v8.1c.ru/8.2/addin/bundle">
    <component os="Windows" path="native_api_search.dll" type="native" arch="x86_64"/>
    <component os="Windows" path="native_api_search32.dll" type="native" arch="i386"/>
    <component os="Linux" path="libnative_api_search.so" type="native" arch="x86_64"/>
</bundle>
Затем:

Создайте ZIP-архив с manifest.xml и DLL;

Загрузите архив как общий макет (например, ОбщийМакет.КомпонентаПоиска) в конфигурацию;

Подключайте в BSL-коде:

bsl
Если Не ПодключитьВнешнююКомпоненту("ОбщийМакет.КомпонентаПоиска", 
        "NativeApiSearch", ТипВнешнейКомпоненты.Native) Тогда
    ВызватьИсключение "Не удалось загрузить компоненту";
КонецЕсли;

Компонента = Новый("AddIn.NativeApiSearch.NativeApiSearch");
13.9. Подключение собранной DLL в 1С
Способ 1 — по пути к файлу:

bsl
ПутьККомпоненте = "C:\Components\native_api_search.dll";
Если Не ПодключитьВнешнююКомпоненту(ПутьККомпоненте, "NativeApiSearch",
        ТипВнешнейКомпоненты.Native) Тогда
    ВызватьИсключение "Ошибка подключения: " + ПутьККомпоненте;
КонецЕсли;

Компонента = Новый("AddIn.NativeApiSearch.NativeApiSearch");
Сообщить(Компонента.HelloWorld());
Способ 2 — через макет в конфигурации (см. раздел 13.8):

bsl
Если Не ПодключитьВнешнююКомпоненту("ОбщийМакет.КомпонентаПоиска",
        "NativeApiSearch", ТипВнешнейКомпоненты.Native) Тогда
    ВызватьИсключение "Не удалось подключить";
КонецЕсли;
Полное имя объекта для Новый() формируется как "AddIn.<ИмяПодключения>.<ИмяСтруктуры>", где <ИмяСтруктуры> — имя структуры из #[derive(AddIn)] (в нашем случае NativeApiSearch) .

13.10. Возможные проблемы при сборке
Проблема	Решение
error: linker 'link.exe' not found	Не установлен MSVC. Установите Visual Studio Build Tools с компонентом «C++ build tools» .
error: could not find 'cargo'	Rust не добавлен в PATH. Перезапустите терминал или выполните source $HOME/.cargo/env .
Не найдена DLL после сборки	Проверьте папку target/<target-triple>/release/, а не target/release/, если указывали --target .
1С не видит компоненту	Убедитесь, что DLL собрана под ту же разрядность, что и клиент 1С (x86 vs x64). Для учебной версии — i686 .
Ошибка зависимостей Tantivy	Tantivy требует свежий Rust (≥1.70). Обновите через rustup update .
